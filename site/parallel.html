Parallel sessions and worktrees

Start as many sessions on one project as you like. Imperatorium makes sure two running sessions never edit the same checkout by accident, and shows you every branch they leave behind.

Four ways to start another session

The Send button's menu sends the prompt in the box to a new session instead of the selected one:

  • Send to New Session: a fresh session in the same project.
  • Send to New Session with Context: a fork of this conversation.
  • Send to New Background Session (ctrl+Enter) and ... with Context (ctrl+shift+Enter): the same, without opening a terminal tab. It reports to the window like any other session.

The New session dialog (from the sidebar menu) picks a project, permission mode, model and effort, and can start the session in the background. History resumes or forks any past session.

Where the new session runs

Every one of those goes through the same rules:

CaseWhere it runs
New session, nobody running in the main checkoutThe main checkout
New session, a session is running thereA new worktree from what the main checkout has checked out
A fork of a running sessionA new worktree from the parent's branch
A fork of a session that has ended, its folder freeThe parent's own folder
Resume, its folder freeIts own folder
Resume, its folder takenA new worktree
Not a git repositoryThe same folder, with a warning

Before a worktree is made the window says so and offers to share the folder instead (Settings > Worktrees turns the question off). A fork of a folder with uncommitted files is always warned about, because a worktree starts from the last commit: it can copy those files in, or start without context. A fork of a session that is mid-turn starts from the end of its last finished turn, so it never sees half a turn.

The new session's first message opens with a short note saying where it is and what else is running, so Claude knows it is not alone.

Seeing the branches

  • The Worktrees tab lists each worktree of the project with the branch it was made from, how far ahead and behind it is, whether it has uncommitted files, and the live sessions in it. Merge it into its base, open a PR, or discard it.
  • Project changes (sidebar menu or View) shows every worktree and branch of a project at once, and first the files more than one of them changes, so a coming merge conflict shows before the merge.
  • From a session in a worktree, View > Merge Worktree Back; Open Folder in Editor opens any session's folder in VS Code.
  • Sessions in a worktree group under their project in the sidebar and in History, with a branch icon.
