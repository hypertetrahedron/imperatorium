Sending work

Send a prompt to any session without visiting it: from the window, the palette, the command line, a script, your voice, or another Claude session.

From the window

Select a session and type. Enter sends to it, even mid-turn. Queue (alt+Enter) holds a prompt until the current turn ends. Stop (or Esc in the prompt box) ends a working turn, as Esc does at its terminal. The Send button's menu starts another session instead; see Parallel sessions.

Quick phrases (ctrl+Space) put your stock lines, like "implement as recommended", into the box at the cursor.

By project name, from anywhere

"project: laser ledger, implement the new feature as recommended" is matched to a project and delivered to that project's running session. With none running, it opens one with the prompt filled in.

imperatorium send -p "gem trip" "fix the failing test"
imperatorium send -p "gem trip" --dry-run "fix it"    # which session would it reach?

A wrong match does not garble text, it fires a prompt at the wrong repository. So matching reports a confidence, and only a certain match is acted on without asking.

As you, or as a peer

With the Imperatorium mod in a session (Claude Code 2.1.287+), a prompt you send from the window is submitted as your own words. Anything that did not come from a person in the window (a script, the command line, another session) arrives framed as another session's message, which Claude Code treats as a request rather than your consent: it cannot answer a permission prompt or change settings. Dispatch sends work; approving what that work then asks for stays a human job.

Slash commands, from the window

A message starting with / runs as a command in the session, not as text. Typing / lists the session's commands (built-in, plugin, skill and MCP), and Tab completes one. The commands that draw something in the terminal are done by the window itself:

  • Pickers for /model, /effort, /fast and /output-style, filled from Claude Code's own lists.
  • Views for /context, /usage, /status, /help, /skills, /hooks and /permissions, and /config as a form.
  • Window features: /resume opens History, /export saves Markdown, /branch forks, /copy copies the last reply.
  • The few that only a terminal can do are refused with a Show Window button and the reason.

From scripts and other agents

The same things the window does are an HTTP API on 127.0.0.1, so a script, a Stream Deck or another tool can drive it. POSTs must be JSON and carry no Origin header, so a web page you happen to have open cannot. The command line covers the common cases:

imperatorium sessions                    # live sessions (* = wants attention)
imperatorium send -s NAME "prompt"       # or -p PROJECT
imperatorium queue add SESSION "prompt"  # held until that session's turn ends
imperatorium resume | fork | new ID      # sessions by id, id prefix or name
imperatorium history worktree            # search past sessions
