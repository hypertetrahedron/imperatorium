Voice, keys and Stream Deck

Get to the right session, and tell it what to do, with as little hunting as possible.

Dictation, on your machine

Hold F9 and speak; let go, and the text lands in the prompt box. Speech is about 150 words a minute against 50 typed. The browser records, and a worker beside the dispatcher transcribes with whisper.cpp on your GPU (or a smaller model on the CPU), so nothing leaves the machine. Near-silence returns nothing, so a fumbled key never invents words.

Voice fills the prompt, never the project. Project names are close to a worst case for speech recognition, and a misheard one would send work to the wrong repository. Picking the session costs one keystroke and removes that failure entirely.

imperatorium voice fetch     # the worker and the models
imperatorium voice status

Hotkey and palette

imperatorium hotkey (Windows) raises the window from anywhere, opening one if none is running. You can give it a list of key choices; the first one Windows grants wins. In the window, ctrl+K jumps to any session by name, j/k move through the list, alt+1-9 picks a tile, and n goes to the next session that wants you.

Quick phrases

ctrl+Space in the prompt box lists your stock phrases ("implement as recommended", "continue as recommended", whatever you add). Type to filter, Enter to insert; nothing is sent until you send it.

Stream Deck

imperatorium streamdeck puts one session on each key, coloured by what it is doing: orange blocked, blue working, green idle, grey no session. A blocked key counts how long it has waited, and a key that changes state flashes for five seconds. Pressing a key raises that exact session, or opens one. Pin your main projects to fixed keys; the other sessions fill the rest, blocked ones first.
