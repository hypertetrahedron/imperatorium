Attention and approvals

At twenty sessions the bottleneck is not how fast agents work, it is how often they stop to ask. Imperatorium brings every ask to one place, the moment it happens, and can answer the cheap ones for you.

Told the moment a session wants you

Claude Code's hooks push permission prompts and questions to the dispatcher as they happen, and it decides a turn is complete the instant it ends. The window's title counts the sessions waiting for you, "(2) Imperatorium", and its tab icon takes the most urgent state's colour and shape. Beyond the window, each of these can be switched on in Settings > Notifications:

  • desktop notifications;
  • spoken alerts;
  • phone pushes through ntfy, which only fire if a session is still waiting a minute later;
  • a Stream Deck key per session that turns amber when blocked and counts how long (see Voice and keys).

Answer from the window

A permission request waits in the window's banner with Allow and Deny until you answer it or hand it back to the terminal. A question (AskUserQuestion) shows as a card with its options, multi-select and free text, one question at a time with a review page before Submit. Requests from remote hosts show in the same banner, led by the host's name. imperatorium pending and imperatorium allow ID do the same from a terminal.

Auto-approval: remove prompts, never answers

imperatorium permission is a Claude Code permission hook that answers the cheap asks (reading a file inside the project, git status, a test run) and forwards everything else to you unchanged.

Anything not provably cheap becomes "ask", which is exactly the prompt you would have had, so you keep the power to approve it. Refusing git push or rm -rf outright would take away your ability to say yes.

  • Deny is kept for one thing: an agent changing the machinery that decides what it may do (settings.json, policy.json, the hooks, --dangerously-skip-permissions).
  • Secrets (.env, keys, .aws/) are never auto-approved, but they are asked about rather than refused.
  • Per project: auto-edit, reads outside the project, extra safe commands, and paths never to auto-approve, in policy.json. The most specific project path wins.
  • Never a black box: every verdict is logged to decisions.jsonl and shown on the board.
  • Fails safe: the hook does no network I/O, and every failure path means "ask".

Auto-approval is off until you turn it on in policy.json, so switching it on is always a choice.

Stop a turn

Stop in the window (or Esc in the prompt box) ends a working session's turn, as Esc at its terminal would.
