Other machines and containers

Sessions on the machines you reach over SSH, and in containers, show and take work just like local ones. The host needs no agent, no daemon and no open port: just a key you already use.

Adding a host

imperatorium remote add HOST              # user@host or an ~/.ssh/config alias
imperatorium remote add HOST --label pi
imperatorium remote check                 # what each host has and lacks
imperatorium remote remove HOST [--purge]

remote add walks through everything a host needs, and every step is safe to repeat: an SSH key login (it offers to make and copy one), Claude Code there (it offers Anthropic's installer), the binary (copied and checked by SHA-256), the reporting hooks, and the host entry in your config.

Or do it from the window: Settings > Remote machines has Add a machine, with Test connection to see what the host has and lacks before adding it, a Test button beside every host already there, and a button to restart the dispatcher once the host is added. If the host refuses the login, the window makes your SSH key and gives you the one command that copies it there; ssh asks the host's password in your terminal, never in Imperatorium. A box on the form installs Claude Code on the host too.

As controllable as a local session

  • Seen: each host is polled over SSH on a thread of its own, so a slow or sleeping host only delays its own sessions.
  • Attention: a reverse SSH tunnel carries the host's hook events back, so its permission prompts and failed turns arrive at once. The tunnel lands on a listener that takes hook events and nothing else, and a host can only describe its own sessions.
  • Prompts: piped over SSH to the session's own inbox on the host. The token travels on stdin, never on a command line.
  • Conversations, cache and cost: read on the host by the same code that reads local ones, over one kept SSH channel, so a read takes milliseconds.
  • Approvals: the host's requests show in your window's banner, led by its name. Nothing is auto-approved on a remote host.

Remote projects are named with their host, devbox/laser-ledger, because firing a prompt at the wrong machine is the same mistake as firing it at the wrong repository.

Containers

A host entry with "container": NAME is reached with docker exec, on this machine or on an SSH host.
