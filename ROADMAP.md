# Roadmap

Status legend: Not Started · In Progress · Complete · Deferred
Last updated: 2026-10-19

Imperatorium (internally Central Control, package `ccontrol`): a single input
surface for dispatching prompts to, and tracking attention across, ~20
concurrent Claude Code projects on this PC plus remote hosts. Published at
https://github.com/hypertetrahedron/imperatorium (MIT).

## Deferred

- **Phone access as an installable web app with Allow/Deny** (survey item 6, deferred by request 2026-10-15) — needs authentication before the dispatcher listens beyond 127.0.0.1, plus a way in such as Tailscale. Unblocked by choosing that and adding a token check to every route.
- **Shared work queue that respects usage limits** (survey item 7, deferred by request 2026-10-15) — a cross-project backlog that starts background sessions while 5h/7d usage stays under a cap. Unblocked by a decision to take it up; the per-session Queue and the usage meter it would build on exist.
- **Send to several sessions at once, saved prompts** (survey item 8, deferred by request 2026-10-15) — e.g. "commit and push" to every selected session, or compact idle sessions before their cache goes cold. Unblocked by a decision to take it up.

- **Bringing a background *tab* to the front** — a session whose tab is not the one its window is showing cannot be raised into view; focus gets the right window and the tab stays behind. Windows Terminal exposes **no `TabItem` elements to UI Automation** (verified by raw ctypes UIA: `ElementFromHandle` and `FindAll` both succeed and return zero tab items on a two-tab window), and `wt.exe focus-tab` needs a window id and tab index that nothing maps a session to. `WT_SESSION` is a per-tab GUID and is readable by a hook, but nothing turns it into a tab index. Until one of those changes, the honest answer is the note the API already returns, naming the tab title to click.

- **servicehost1** — has never run Claude Code, so there is nothing to poll. developmenthost1 (2026-09-17) and raspberrypi.local (2026-09-24, after updating from 2.1.49, which had no `agents --json`) are done. Unblocked by installing Claude Code there; `python setup_machine.py remote add servicehost1 --install-claude` now does that and the rest.
- **amux adoption** — github.com/mixpeek/amux is the closest existing thing to the desired fleet dashboard (SSE live status, task board, mobile PWA), but it wraps tmux (or `herdr`, whose Windows binary is 0.8.0-preview) and ships only launchd/systemd installers. Not viable on bare Windows 11 without WSL. Notably it does not use `claude agents --json`, so a Windows-native equivalent built on the supported API would be simpler than adopting it. Revisit if herdr's Windows support leaves preview.
- **Tiling window manager (komorebi / GlazeWM)** — would give named-workspace-per-project with scripted focus-by-name, and both sidestep the fragile virtual-desktop API by design. Deferred because it replaces the whole window-management model for a problem that mostly disappears once dispatch and attention routing exist. Revisit if window navigation is still painful after Phase 2.
- **WezTerm migration** — `wezterm cli send-text --pane-id` + `activate-pane` is the one verified way to inject text into an arbitrary pane running an interactive TUI and then focus it. Deferred in favour of first-party dispatch (`--bg`, channels, cross-session messaging), which does not require migrating every session off Windows Terminal. Revisit if first-party dispatch proves insufficient.
- **Third-party multi-session managers** — Claude Squad, ccmanager, Uzi, dmux all require WSL (tmux-based); Conductor is macOS-only; Crystal was deprecated Feb 2026; Vibe Kanban is sunsetting; Terragon shut down Jan 2026. Their core value (parallel sessions, per-session status, worktree-per-session) is now native.
