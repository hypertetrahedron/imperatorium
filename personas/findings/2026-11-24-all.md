## Recommendations

Ordered by how much time or work they cost a user, then by how many
personas hit them. Effort: S (an afternoon), M (a day or two), L (more).

### Priority 1: work goes missing or the user is stuck

**1. Keep an unreachable host's sessions on the list, and let the window retry it.** (Rhea, Remy; confirmed in code; M)
When a poll fails, `RemoteFleet::poll_host` stores no rows, so the host's
sessions leave the list and the sidebar says "no sessions". A failed host
is then parked for 60 s, doubling with each failure up to 15 min
(`remote_backoff_start`, `remote_backoff_max`), so a host that has come
back stays hidden: 26 s for Rhea after one drop; for Remy's flapping host,
over 35 s and still missing when the step ended. **Refresh now** brought
it back in 0.4 s, but it exists only in the Settings window (a new window,
three clicks). A prompt typed while the host was down went nowhere, with
no message.
- Keep the last rows, marked unreachable, with the ssh error and when the next try is.
- Put Refresh now (or "retry this host") in the main window, on those rows.
- Reset or shorten the back-off for a host that was answering until a moment ago; keep the long back-off for hosts that have never answered.
- Refuse a send to an unreachable host with a reason, instead of dropping it.

**2. A prompt can be lost from the queue, and a queued prompt can be duplicated.** (Max; confirmed in code; S)
- `queue()` clears the prompt box when the server answers, so anything typed or pasted during that round trip is wiped (one of Max's three prompts vanished). Clear the box only if it still holds the text that was queued.
- After a queued prompt is cancelled, the list is not redrawn until the next poll. A second **cancel** hits the item already removed, is refused without a word, and the item Max meant to cancel ran twice (seen in both runs where he moved one). Redraw at once after unqueue, and show a refusal.
- Queued prompts cannot be reordered: the only control is cancel. Add move up / move down, or drag.

**3. First run: no project folder, then a restart the window cannot do.** (Nell; confirmed in code; S-M)
- With `roots` empty, the catalogue falls back to the parent of the config folder (`views.rs catalogue`). On an installed machine that is `%APPDATA%`, so New session lists every folder there as a project. In the sandbox it listed `bin`, `claude`, `state` and the like. Replace the fallback with an empty state: "No project folders yet. Add one in Settings."
- A saved project folder applies only "after a dispatcher restart", and the window offers no restart. Nell's first session cost 36 s, most of it finding and running the restart. Read `roots` live (it is a catalogue read), or offer "Restart now", as Add a machine already does.

**4. Send is greyed out on remote sessions, but Enter sends.** (Rhea, Remy; confirmed in code; S)
`drawHead` disables `#send` for any remote row, while Enter's `send()` has
no such check, and delivery works (26-187 ms to each of Remy's five
hosts). Enable Send when the row can be sent to; otherwise say why.

**5. `/api/dispatch`: an unknown `mode` opens a window, and a dry run cannot name a session.** (June; confirmed in code; S)
- `mode` is not checked. A typo (`"sideways"`) falls through to launch and opens a new terminal window. Refuse unknown modes with the list of valid ones, as the CLI's `send --mode` and `/api/fleet/action` already do.
- A `session_id` is honoured only in `auto` and `inject` modes. With `dry-run` it falls through to project routing and is refused ("no project named"), so `imperatorium send PROMPT -s SESSION --dry-run` always exits 1. Let a dry run say what would happen to that session.

### Priority 2: time lost every day

**6. `n` should go to blocked sessions first.** (Tessa; confirmed in code; S)
`nextWaiting` orders sessions by `attention_since`, so a session blocked
on a permission request ranks with ones that merely finished. With 16
sessions it took 6 presses in one run and 11 in another. Rank permission
requests and questions first, or give them their own key.

**7. Permission requests: show them at once, and give them keys.** (Tessa, Kai; confirmed in code; M)
`drawPending` polls every other 1.5 s tick: 2.4-3.8 s from park to the
Allow button, for the one thing that stops a session. Push it on the
stream. Question cards have 1-9 and Enter; Allow / Deny rows have no keys,
so the keyboard user reaches for the mouse. Add keys and a hint.

**8. Esc should close every pop-up.** (Ines, Omar, Basil; confirmed in code; S)
Esc is handled on each pop-up's own `keydown`, so it works only while
focus is inside. History focuses its search box and Project changes its
Refresh button, but Insights moves no focus, so Esc does nothing until you
click inside it (3 of 3 tries). After a merge in Project changes, focus
leaves the pop-up and Esc stops working (Basil, both runs). Handle Esc at
the document level whenever a pop-up is open.

**9. The Changes tab shows the previous session's diff after a switch.** (Ines; observed, consistent with `loadChanges`; S)
For 0.8-1.2 s after selecting another session, the Changes tab keeps the
old session's diff under the new session's title, and a click on a line
does nothing, because the handler checks the key. Clear it or mark it
loading on switch. Related: after **Send to session**, the reply arrives
on the Conversation tab while the reviewer is still on Changes. Switch
tabs, or say where the answer is.

**10. Worktrees: fewer git round trips and fewer steps.** (Wren, Basil, Ines; observed; M-L)
- Latency in a five-commit repository, release and debug alike:
  - Worktrees tab: 1.3-1.9 s.
  - Merge and discard: 1.5-2.2 s.
  - Changes: about 1 s.
  - Spawn plan: 0.7-1.5 s.

  Count the git processes per endpoint, batch them, and cache by HEAD and index mtime.
- Discarding a worktree with unmerged commits asks twice: a confirm, a server refusal, then a second confirm. Make it one dialog that states the count.
- A merge reports only in the say line, and the card stays at "0 ahead". Show the result on the card and offer "Merge and remove".

**11. History: read before resuming, and get out of the way after.** (Arlo, Sol; observed; M)
- A past session cannot be looked at without resuming it: its hit offers only Resume, Resume in bg, Fork and Copy cmd. Add a read-only view of the transcript in the chat area; no process is needed.
- After Resume, the History pop-up stays open over the new session (Sol, Arlo). Close it.
- The first search over 500 sessions took 2.6-3.4 s; later ones take about 0.2 s. Warm the index at start.

**12. Background job from New session: give it a task field.** (Basil; observed; S)
With the background box ticked, the prompt box is the task, so opening the
dialog first (the natural order) starts the job idle, and it then needs
finding and a second send: 16 s, Basil's costliest step. Add a task box,
prefilled from the prompt box.

**13. Show which machine a remote tile is on.** (Remy; observed; S)
With the same checkout on five hosts, the list showed five "svc-0" and
four "svc-1" tiles, and only the open tile's Meta Line names its host.
There is no "by host" grouping. Put a host badge on every remote tile and
add "by host" to the group selector.

### Priority 3: polish

14. **Closing a session** takes four interactions: open its tile, ✕, confirm (Wren, Basil). Show ✕ on hover for any tile, and skip the confirm for an idle session.
15. **Insights' two range pickers differ**: cost offers 7/30/90 days, tool failures 1/7/30 (Omar). One range for the pop-up.
16. **Forks are named after their first prompt** ("side-question-why-are", "and-check-the-tangent") with nothing linking them to the session they came from (Max). Show "fork of engine" on the tile.
17. **The prompt-cache countdown** shows as a bare "-5" on every tile (set 1). Label it, or show it only on hover.
18. **Polling**: one window makes 88-420 API calls a minute, led by `/api/awaited` and `/api/conversation`; `/api/usage` p95 is 408 ms. Unseen at this scale, but it multiplies with windows and hosts. Move the busiest polls to the stream.
19. **alt+1-9** follows list order, which changes as states change, so it is not a stable way back to one session (Kai).

## Corrections to set 1

- Set 1 said there is no way to poll a host again. There is one, **Refresh now**, but only in the Settings window (recommendation 1).
- Basil's "Esc did not close Project changes after a merge" is explained: focus leaves the pop-up (recommendation 8). It happened in both runs.
- The 9.3 s close time is still a simulation artifact: the dispatcher waits up to 8 s for `/exit`, and the simulated process does not read its console.

## What works well (no action needed)

- **Slash commands**: the `/model` and `/effort` pickers open in 26-36 ms, and a choice reaches the session in 1.1-1.6 s. `/config` shows as a form (2 s, through the mod). Autocomplete shows in 34 ms and says what each command does from the window. `/resume` opens History on the session's folder.
- **Cost**: Insights loads in 0.1-0.2 s for 7, 30 or 90 days, with tables by project and by model. The meter's spend lines and the Model Mix are one click away. A spend watch is added in 0.1 s.
- **History** over 500 sessions in 20 folders: the folder filter, sort and range answer in about 0.2 s. Resuming into a taken folder asks the worktree question and starts in 4-6 s.
- **Scripts** (June):
  - Refusals are plain and specific: "no project matched 'no-such-project'", "no prompt", "expected an object". Window-only endpoints answer 403 with a reason.
  - A proposed watch shows in the window in 1.1 s, an action in 2.9 s. A confirmed action reaches the session framed as Imperatorium's message, not the person's.
  - The CLI's other commands (`sessions`, `projects`, `queue`, `pending`, `history`) answer in 40-50 ms.
- **Interrupting** (Max): Esc stops a turn in 0.3 s, and the redirect lands 2.4 s after Esc. A mid-turn fork starts from the last finished turn.
- **Adding a machine** (Nell): the test explains a refused login and offers key login. The key was made inside the sandbox; the persona harness now points `USERPROFILE` there.
- **Set 1's fast paths still hold**: ctrl+K, j/k and switching are each under 0.2 s; a 400-turn chat opens in 57 ms; a burst of approvals takes under 1 s.
- **Memory**: the dispatcher's working set stayed at 19-36 MB.

## Withdrawn or simulation-only

- **The empty `/model` picker** ("Claude Code's list is not loaded yet"): a test copy of the dispatcher probes Claude Code only when `IMPERATORIUM_CLAUDE_PROBE` is set. The sandbox now sets it, and the picker lists the models at once.
- **"No session id was printed"** for a background start on a host: the stub printed an id the dispatcher's pattern rejects. The stub is fixed; the start works.
- **Fork of a fork refused** ("it has not finished a turn yet"): when the session being forked is mid-turn, the dispatcher cuts at its last finished turn. A real fork's transcript carries the parent's history; the simulated fork's does not, so the cut finds nothing. This is Max's one failed step.

## Limits of this run

- One run per persona (two or three for some while the harness was fixed). The timings are indicative, not distributions.
- Claude Code is simulated:
  - A launched session appears 2.5 s after launch.
  - The mod beats every 2 s.
  - Turns take seconds.
  - Forks carry no history.
  - Fleet Ask's answer is canned.

  Remote hosts are a stub ssh that answers from files.
- The estimated human time is the Keystroke-Level Model plus the measured waits. It counts decisions and pointing, not reading or typing a prompt's words.
- **Harness defects fixed in this pass** (none of them product findings):
  - the stub's model catalogue and remote background id;
  - `USERPROFILE` pointed into the sandbox;
  - a dispatcher restart;
  - the simulated mod's `/config` rows;
  - the remote inbox payload parsed properly;
  - a skill name that collided with a built-in (`/release-notes`);
  - waits that measured a list mid-redraw;
  - typing faster than a person can.
